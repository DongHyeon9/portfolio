내부망 Linux 서버 구축

Windows 데스크톱을 Ubuntu Server 26.04 LTS 기반의 내부망 서버로 전환한 프로젝트입니다. 운영체제와 디스크를 정리하고, OpenSSH와 WireGuard로 작업실 내부와 외부의 관리 경로를 나눴습니다. 인터넷에는 VPN 포트 하나만 열고 SVN 저장소는 LAN 또는 VPN 안에서만 접근하도록 구성했습니다.

OVERVIEW

서버 기반을 먼저 분리했습니다

애플리케이션 배포 자동화보다 앞단의 서버 설치, 저장공간, 원격 관리, 외부 접속 통로와 형상관리 저장소에 집중했습니다. 서비스 운영 도구는 이 기반 위에 별도 프로젝트로 구성합니다.

2개 접근 경로작업실 LAN 또는 WireGuard VPN

BUILT

구축 항목

Windows 환경의 데이터는 보존하면서 서버 운영체제와 접근 경로를 새로 설계했습니다.

01 · OS

Ubuntu Server 설치

  • 기존 SVN 저장소 백업 후 Windows 제거
  • BIOS를 UEFI로 설정하고 LVM으로 설치
  • OpenSSH를 포함한 GUI 없는 26.04 LTS 구성
02 · DISK

디스크 역할 분리

  • 500GB HDD는 OS, 512GB SSD는 /data
  • 4TB HDD는 /backup과 SVN 저장소
  • GPT · ext4로 정리하고 UUID 기반 fstab 적용
03 · SSH

내부 원격 관리

  • OpenSSH를 부팅 시 자동 시작
  • UFW에서 LAN 대역과 wg0의 TCP 22만 허용
  • 모니터와 키보드 없이 원격으로 운영
04 · VPN

WireGuard 외부 접속

  • 서버 wg0에 VPN 대역 10.10.0.0/24 구성
  • 기기마다 별도 공개키와 VPN IP 할당
  • wg-quick@wg0로 부팅 후 자동 기동
05 · NAT

포트포워딩 최소화

  • 공유기에서 UDP 51820만 서버로 전달
  • DHCP 예약으로 서버 내부 IP 고정
  • SSH 22와 SVN 80은 인터넷에 직접 공개하지 않음
06 · SVN

Apache SVN 구축

  • mod_dav_svn과 SVNParentPath로 여러 저장소 제공
  • htpasswd bcrypt 인증과 authz 권한 분리
  • Windows VisualSVN 저장소를 Linux 호스트 구조로 전환

ARCHITECTURE

접속 흐름과 저장공간

외부 사용자는 먼저 WireGuard 터널을 만든 뒤 내부 서비스에 접근합니다. 같은 작업실 LAN에서는 포트포워딩 없이 서버 내부 IP로 접속합니다.

IP 대역은 구성 설명을 위한 예시입니다. 인터넷에 직접 공개되는 것은 WireGuard UDP 51820뿐이며, SSH와 SVN은 VPN 터널 또는 신뢰하는 LAN에서만 접근합니다.

TECHNOLOGY

기술 선택과 이유

각 기술은 기존 구축 기록에서 확인되는 역할과 운영 조건을 기준으로 정리했습니다.

기술사용 이유
Ubuntu Server 26.04 LTSGUI 없이 SSH로 관리하는 서버 환경과 장기 지원 버전을 사용해, 데스크톱 PC를 전용 서버로 전환했습니다.
LVM · GPT · ext4 · fstab잘못 설치된 LVM 흔적을 정리하고 OS와 데이터 디스크를 구분했습니다. UUID 기반 fstab과 nofail로 장치 이름 변경이나 보조 디스크 문제에 대비했습니다.
OpenSSH · UFW모니터 없이 서버를 관리하되 TCP 22 접근을 LAN 대역과 WireGuard 인터페이스로 제한했습니다.
WireGuard외부 기기별 공개키와 전용 IP로 접속을 구분하고, SSH와 SVN 포트를 인터넷에 직접 노출하지 않는 단일 진입점을 만들었습니다.
공유기 DHCP 예약 · NAT포트포워딩 대상 IP가 바뀌는 문제를 막고, 외부 규칙을 UDP 51820 하나로 최소화했습니다.
Apache · mod_dav_svnSVNParentPath로 여러 저장소를 한 경로 아래 제공하고, 기존 VisualSVN 저장소를 Linux 호스트에서 이어서 운영했습니다.
htpasswd · mod_authz_svnbcrypt 비밀번호 인증과 저장소별 읽기·쓰기 권한을 분리해, 인증된 모든 사용자가 커밋할 수 있는 구성을 피했습니다.

SECURITY

외부 노출과 권한을 줄였습니다

네트워크

VPN을 유일한 외부 입구로

공유기에는 UDP 51820만 포워딩하고, SSH 22와 SVN 80은 직접 공개하지 않았습니다. 외부에서는 WireGuard 핸드셰이크가 먼저 성립해야 내부 서비스에 닿습니다.

방화벽

접근 출발지 제한

UFW 규칙은 신뢰하는 LAN 대역과 wg0 인터페이스에서 오는 연결만 허용합니다. 포트를 열어 두는 것과 서비스가 실제로 리스닝하는 것도 각각 확인했습니다.

SVN 권한

인증과 쓰기 권한 분리

htpasswd 계정 인증에 더해 authz로 관리자만 쓰고 일반 인증 사용자는 읽도록 구분했습니다. 저장소 파일은 Apache의 www-data가 관리합니다.

한계

LAN 구간의 HTTP

WireGuard 구간은 암호화되지만 LAN에서 사용하는 SVN HTTP는 평문입니다. 신뢰할 수 없는 LAN까지 고려한다면 LAN 허용을 제거하고 VPN 주소만 쓰거나 내부 HTTPS를 추가해야 합니다.

내부망 Linux 서버 구축 · 실제 공인 IP, 계정명, 디스크 UUID와 키는 이 페이지에서 제외했습니다.
