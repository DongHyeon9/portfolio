jenkins-local-test

Jenkins 파이프라인으로 VPN · SVN · Jenkins 계정을
한 번에 만들고 고치고 지우기

LAN 서버 한 대에서 운영하는 WireGuard VPN, SVN(Apache), Jenkins 세 시스템의 사용자 계정을 Jenkins 파이프라인 3개(생성 · 수정 · 삭제)로 관리하는 프로젝트입니다. 관리자가 Jenkins 화면에서 파라미터만 입력하면 세 시스템에 같은 사용자가 스테이지별로 반영되고, 중간에 실패하면 완료된 단계만 되돌립니다. 파이프라인 정의 자체도 SVN에 커밋하면 자동으로 Jenkins에 반영됩니다.

OVERVIEW

개요

사용자 한 명을 추가하려면 원래 서버에 SSH로 들어가 wg0.conf에 peer를 넣고, htpasswd로 SVN 계정을 만들고, Jenkins 화면에서 계정과 권한을 따로 만들어야 했습니다. 이 프로젝트는 그 작업을 Jenkins 잡으로 옮기고, 잡 정의까지 저장소 코드로 관리합니다.

문제

계정이 세 곳에 흩어짐

VPN · SVN · Jenkins 계정을 각각 손으로 관리하면 이름이나 비밀번호가 어긋나고, 삭제할 때 한 곳을 빠뜨리기 쉽습니다. 서버 root 권한도 매번 필요합니다.

해결

사용자 1명 = 잡 1회 실행

vpn-user-create / update / delete 잡이 세 시스템을 스테이지별로 처리합니다. root 작업은 검증된 CLI 하나(vpn-user)만 sudo로 허용합니다.

운영

커밋 = 배포

pipelines/ 아래에 Jenkinsfile을 추가 · 삭제하고 커밋하면 post-commit 훅 → seed 잡이 잡과 상단 탭을 만들거나 지웁니다. Jenkins 홈은 저장소에 두지 않습니다.

FEATURES

주요 기능

세 잡 모두 관리자만 실행할 수 있고, 같은 잠금(lock('vpn-user'))을 공유해 동시에 같은 사용자를 바꾸지 못합니다.

create

사용자 생성

  • 입력: 사용자명 · 비밀번호(SVN · Jenkins 공용) · WireGuard 공개키 · 권한
  • VPN 대역에서 다음 빈 IP를 자동 할당
  • 마지막에 WireGuard 앱에 붙여넣을 클라이언트 설정을 로그로 출력 (개인키는 서버가 모르므로 출력하지 않음)
update

사용자 수정

  • 드롭다운에서 사용자 선택 → 이름 · 비밀번호 · 공개키 · 권한 중 입력한 항목만 변경
  • 입력이 없는 시스템의 스테이지는 when으로 건너뜀
  • 이름 변경 시 SVN 비밀번호 해시와 Jenkins 권한 항목을 새 이름으로 이동
delete

사용자 삭제

  • 드롭다운에서 선택 → Jenkins → SVN → WireGuard 순서로 삭제
  • 모든 단계가 멱등이라 중간 실패 시 같은 사용자로 다시 실행하면 마무리
  • 실행한 관리자 본인은 삭제 · 관리자 해제 불가 (관리자 잠김 방지)

Jenkins 권한 역할

역할부여 권한 (matrix-auth)
관리자Overall/Administer — 사용자 관리 잡 포함 전체
일반Job/Build, Job/Cancel — 조회는 로그인 사용자 공통 권한
읽기전용추가 권한 없음 — 로그인 사용자 공통(Overall/Read, Job/Read)만

역할을 따로 저장하지 않고 Jenkins 권한 설정 자체를 원본으로 씁니다. 사용자별 항목이 없으면 읽기전용입니다.

WORKFLOW

워크플로

① 파이프라인 코드가 Jenkins에 반영되는 흐름과 ② 사용자 생성 잡이 실제로 서버를 바꾸는 흐름입니다.

① 커밋 → 잡 자동 생성 (seed)

subversion 플러그인의 notifyCommit은 최신 Jenkins에서 CSRF crumb을 요구해 403이 나므로, build-token-root 토큰 엔드포인트로 seed를 호출합니다. 훅은 실패해도 커밋을 막지 않고 syslog에만 기록합니다.

② 사용자 생성 잡 (vpn-user-create)

생성은 WireGuard를 먼저, 삭제는 WireGuard를 마지막에 처리합니다. peer 태그(관리 대상 표시)가 있어야 SVN 명령이 허용되기 때문에, SVN 단계는 항상 관리 대상 사용자만 건드리게 됩니다.

TECH STACK

사용 기술과 선택 이유

새 플러그인이나 외부 패키지를 최소로 두고, 서버에 이미 있던 도구(SVN · WireGuard · Docker)를 잇는 데 집중했습니다.

기술왜 사용했는지
JENKINS
Jenkins LTS (Docker Compose)서버에 이미 컨테이너로 운영 중이던 Jenkins를 그대로 씁니다. 홈 디렉터리만 호스트에 보존하고, 포트는 LAN · VPN 두 주소에만 바인딩해 다른 인터페이스로는 노출하지 않습니다.
Declarative Pipeline시스템(WireGuard · SVN · Jenkins)마다 스테이지를 나눠 Stage View에서 어느 단계가 성공 · 실패 · 건너뜀인지 바로 보이게 했습니다. post { failure }로 롤백, when { beforeAgent true }로 불필요한 호스트 접속을 생략합니다.
Job DSL + seed 잡디렉터리 1개 = 잡 1개, 2단계 디렉터리 = 상단 탭으로 규칙화해 잡을 화면에서 만들지 않습니다. 재생성 때 Job DSL이 지우는 잡 속성(파라미터)은 기존 <properties>를 복사해 보존합니다.
전역 Groovy 라이브러리 (vars/)Jenkins 계정 · 권한 · 드롭다운 파라미터처럼 Jenkins API가 필요한 로직을 세 잡이 공유합니다. 전역 라이브러리는 샌드박스 밖에서 실행되므로 저장소 쓰기 권한을 관리자로 제한했습니다.
init.groovy.d (bootstrap)자격증명 · SSH 노드 · 라이브러리 · 권한 · seed 잡을 Jenkins 기동 시 멱등하게 설정합니다. 화면 클릭 없이 서버를 재구성할 수 있고, 비밀값은 저장소가 아닌 임시 파일로 받아 등록 후 지웁니다.
matrix-auth관리자 · 일반 · 읽기전용 3개 역할을 사용자별 권한 항목으로 표현합니다. 별도 역할 저장소 없이 Jenkins 설정 자체를 원본으로 둡니다.
build-token-root · lockable-resources · pipeline-stage-view훅이 로그인 없이 토큰으로 seed를 호출하고(crumb 403 회피), 세 잡을 하나의 잠금으로 직렬화하며, 잡 화면에 스테이지 표를 띄우기 위해 추가했습니다.
SSH 에이전트 노드 (label host)Jenkins 컨테이너에는 python3가 없고 WireGuard · SVN 파일은 호스트에 있으므로 호스트 자체를 에이전트로 붙였습니다. 호스트 키를 미리 받은 값으로 고정 검증합니다.
HOST · SCRIPT
Python 3 (표준 라이브러리만)root 작업을 vpn-user CLI 하나로 모았습니다. 파라미터를 신뢰할 수 없는 입력으로 보고 이름 · 공개키(32바이트 base64) · 비밀번호를 검증하며, flock 잠금과 임시 파일 + os.replace 원자적 쓰기로 동시 실행과 중간 종료에 대비합니다. 외부 명령은 셸을 거치지 않고 인자 리스트로 실행합니다.
unittest설정 파일 처리를 문자열만 다루는 순수 함수로 분리해, Windows 개발 PC에서도 root · wg 없이 18건의 테스트를 돌립니다.
sudoers (설치본 1개만)에이전트 계정이 바꿀 수 있는 저장소 사본이 아니라 root 소유 설치본 /usr/local/sbin/vpn-user만 NOPASSWD로 허용해, 파일 교체로 root 권한을 얻는 경로를 막습니다.
WireGuardpeer를 wg0.conf에 기록하는 동시에 wg set으로 실행 중인 인터페이스에도 바로 반영해, 재시작 없이 접속이 열리고 닫힙니다.
Apache SVN + post-commit 훅서버에서 이미 운영 중이던 SVN을 그대로 파이프라인 저장소로 사용합니다. 커밋 직후 훅이 seed를 호출하고, 실패해도 커밋을 막지 않도록 항상 0으로 종료합니다.
Bash (setup-host.sh) · ufwJRE · 에이전트 계정 · sudoers · 훅 · 플러그인 · 방화벽을 한 번에 적용하는 멱등 설치 스크립트입니다. 컨테이너 대역을 고정해 ufw로 호스트 22(SSH) · 80(SVN)만 허용합니다.

DECISIONS

문제 해결 기록

계획 문서(plans/01~12)에 남긴 결정 중 핵심만 정리했습니다. 각 단계는 실서버에서 테스트 사용자를 만들고 지우며 검증했습니다.

버그

커밋하면 파라미터가 사라짐

Job DSL이 잡 설정을 통째로 다시 만들면서 Jenkinsfile이 등록한 파라미터를 지워, 커밋 직후 생성 잡이 파라미터 없이 실행되어 실패했습니다. seed가 기존 잡의 <properties>를 복사해 보존하도록 고쳤습니다.

개선

파라미터 변경이 다음 실행에야 보임

선언형 parameters {}는 잡이 한 번 실행돼야 등록됩니다. seed가 바뀐 잡만 "파라미터 갱신 실행"으로 트리거하고, 그 실행은 첫 스테이지에서 NOT_BUILT로 바로 끝나게 해 커밋만으로 반영되게 했습니다.

설계

동적 드롭다운을 플러그인 없이

사용자 목록은 실행 시점마다 달라 정적 파라미터로 표현할 수 없습니다. 수정 · 삭제 잡은 parameters를 선언하지 않고, 잡이 성공할 때마다 라이브러리가 호스트의 사용자 목록으로 파라미터 정의를 직접 교체합니다.

보안

기존 계정 보호

파이프라인 이전부터 있던 SVN 계정이나 손으로 넣은 VPN peer를 실수로 바꾸지 않도록, 태그된 peer와 관리 목록에 있는 이름만 수정 대상으로 제한했습니다. 기존 사용자는 1회성 register 명령으로 편입합니다.

보안

비밀번호를 로그에 남기지 않기

비밀번호는 셸 환경 변수 → stdin으로만 전달하고(ps 노출 방지), set +x로 트레이스를 끕니다. Groovy에서는 입력 여부만 확인하고 평문은 @NonCPS 함수 밖으로 꺼내지 않습니다.

운영

실패해도 다시 돌리면 끝나게

생성 · 수정은 완료 표시된 단계만 역순 롤백하고, 삭제는 되돌릴 수 없는 대신 모든 단계를 멱등으로 만들어 재실행으로 마무리합니다. 부가 단계(목록 갱신 · 클라이언트 설정) 실패는 UNSTABLE로만 표시합니다.

jenkins-local-test · 서버 주소 · 계정명 · 비밀값은 이 페이지에서 제외했습니다.
